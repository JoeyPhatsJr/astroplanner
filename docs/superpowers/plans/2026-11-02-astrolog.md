# AstroLog (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build AstroLog: import Seestar/Canon files by header (no typing) into a target-first library that shows each target's final picture, time in the final stack and time captured, linked to Phase 1 plans and Tonight's cards.

**Architecture:** Backend gains an `app/astrolog/` package (header parsing, import grouping, previews, storage, library queries) behind new `/api/astrolog/*` routes, with Alembic migrations (Phase 1 baseline + Phase 2 tables). The browser reads only header byte-slices of files from a chosen folder and posts them in batches; only the chosen final picture is uploaded to make a metadata-free preview. Frontend adds Import, Library and Target pages under `/astrolog` plus a history badge on target cards.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Astropy (FITS), exifread (CR2), tifffile + NumPy + Pillow (previews), React 19 + TypeScript + TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-astrolog-design.md` (read §2, §3, §7, §7a and §9 before starting any task).

## Global Constraints

- Preserve Phase 1: `backend` 66 tests, `frontend` 23 unit + 10 e2e tests stay green after every task.
- No SQLite-only SQL; migrations must run on SQLite and Postgres (`DATABASE_URL`).
- Coordinates read from files (`SITELAT`/`SITELONG`) are never stored, returned, logged or written into previews.
- Never estimate missing values: unknown stays `null` and the UI says "unknown".
- Stack times are never summed; headline = linked stack's integration, else captured time labelled "captured".
- Night of a frame = Phase 1 rule: local noon→noon in the location's IANA timezone containing `DATE-OBS` (UTC).
- Canon EXIF times are local time of the user-chosen location (+ optional clock offset).
- Final-picture upload limit 150 MB; preview ≈1600 px long edge JPEG, thumbnail ≈400 px, both metadata-free.
- Header slices: FITS = 2880-byte blocks until the `END` card (cap 10 blocks); CR2 = first 131072 bytes.
- Ignore on import: any path segment `process`; filenames starting `pp_`, `r_`, `.`; extensions `.seq`, `.lst`, `.txt`, `.dylib`, `.onnx`, `.mp4`.
- UI follows the Phase 1 "Clean Planetarium" theme tokens and night-vision mode; all inputs labelled; loading/error/empty states.
- Real-data test reads `ASTROPLANNER_REAL_DATA`, is skipped when unset, prints no coordinates or serials.

## Review Focus

1. **One folder spanning midnight with two targets** (e.g. M 27 20:28–22:31 then NGC 7635 23:11–05:44 local) → one session, two capture sets, both on the evening's night date. Test in Task 4.
2. **A `.fit` file that is truncated or not FITS** → listed under `skipped` with a reason; the rest of the batch imports. Test in Task 3 and Task 4.
3. **Re-importing a folder after more frames were added** → only new frames are inserted and captured totals grow; nothing doubles. Test in Task 4.
4. **Headers whose coordinates match no saved location** → preview returns `needs_location: true` with no coordinate fields anywhere in the JSON; commit without `location_id` is rejected with 422. Test in Task 4.
5. **Final picture in an unsupported or oversized format** (`.CR2`, `.mp4`, >150 MB) → 415 / 413 with a readable message, nothing stored. Test in Task 5.
